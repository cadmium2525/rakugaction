# ランキングに 3D の姿を載せる + 管理者による審査

**状態: 実装済み (v0.17.0)。ただし、本物の Firebase ではまだ動かしていない** (このリポジトリには Firebase のプロジェクトが無い)。
下の「5. 準備の手順」でプロジェクトを作ってから、「7. 最初に確かめること」を行う。
ランキングの基本 (タイムの検査・無料枠・設定ファイル) は `docs/RANKING.md`。

## 1. 決めたこと

| 項目 | 決定 |
|---|---|
| 不適切な絵の判定 | **コードによる自動判定はしない** (形の規則は誤判定が多く簡単に抜けられる・ブラウザ側の判定は書き換えられる)。**管理者が目で見て決める** |
| 公開の時期 | **承認してから出す**。タイムと順位は登録した瞬間に載る。姿 (3D) と名前は、承認されるまで「審査中」 |
| 審査の範囲 | **TOP 20** (順位の高い順に審査)。それより下は「審査中」のまま |
| 管理者の道具 | **ゲームとは別のアプリ** (`/admin/`)。同じリポジトリの中の別のページで、ゲームと同じサイトで公開する。今後、ランキング以外の管理機能も足せる |
| 管理者のログイン | **Google アカウント** |
| プレイヤーのログイン | **しない**。ランキングへの登録・通報の時だけ、裏で匿名の ID を作る (画面は出ない。今までと同じ) |
| 通報 | **入れる**。承認された記録の姿を見る画面に「⚑ 通報」。承認の見落としを管理者に知らせる |

「載せてから消す」にしない理由: 登録は匿名の ID で行うので、消された人はブラウザのデータを消すだけで新しい ID になり、同じ絵を載せ直せる。
承認するまで出さなければ、問題のある絵が人目に触れる時間がなく、載せ直しも意味がない。

## 2. 見え方 (ゲームのランキング画面)

| 記録の状態 | 一覧での名前 | 姿 | 説明 |
|---|---|---|---|
| **承認** (`approved`) | 付けた名前 | 👁 を押すと 3D (回して見られる) | 管理者が確認した |
| **審査中** (`pending`) | 体型タイプ名 (「高速型」など) + TOP 20 なら「審査中」の印 | 見られない (👤) | 登録した直後・絵か名前を変えた直後・TOP 20 より下 |
| **非表示** (`hidden`) | 体型タイプ名 | 見られない | 管理者が掲載できないと判断した。タイムと順位は残る |
| (削除) | — | — | 記録そのものを消す。あわせて、その匿名 ID の再登録を禁止できる |

* **本人には、自分の名前と姿がいつも見える**。画面の下に状態を出す:「審査中」「公開されています」「この絵または名前は、ランキングに掲載できません」。
* 登録する前に注意を出す:「登録すると、キャラクターの絵と名前がランキングで公開されます (確認のあと)。不適切な絵・名前は掲載されません」。
* 姿を見る画面の「⚑ 通報」: 確認のダイアログ → 管理者アプリの「通報」に出る。同じ記録は 1 人 1 回。

## 3. データとルール

記録 (`ranking/{uid}`) に 2 つの値を足した (`schemaVersion` = 2)。

| 値 | 内容 | 書ける人 |
|---|---|---|
| `look` | ラクガキの絵を小さく詰めた文字列 (`src/ranking/look.ts`)。`''` = 姿なし | 本人 |
| `status` | `pending` / `approved` / `hidden` | **管理者だけ** (本人が書けるのは `pending` だけ) |

ほかに 3 つの集まりがある。

| 集まり | 内容 | 読める人 | 書ける人 |
|---|---|---|---|
| `admins/{uid}` | 管理者の印 | 本人 (自分が管理者かを確かめる) | **だれも書けない** (Firebase の管理画面で手で作る) |
| `banned/{uid}` | 再登録を禁止した匿名 ID | 管理者 | 管理者 |
| `reports/{記録の uid}_{通報した人の uid}` | 通報 | 管理者 | ログインした人が、1 つの記録につき 1 回だけ作れる (消せるのは管理者) |

### ルール (`firebase/firestore.rules`。ブラウザ側のコードは信用しない)
* 本人が**新しく登録**する時: `status` は `pending` でなければ拒否。
* 本人が**更新**する時 (今までどおり、タイムが縮んだ時だけ):
  * 絵 (`look`) と名前が前と同じなら、`status` は前のまま (承認済みのキャラでタイムだけ縮めても、承認は続く。自分で `approved` に上げる・`hidden` を `pending` に戻す、はどちらも拒否)。
  * 絵か名前が変わったら、`status` は `pending` でなければ拒否 (審査し直し)。
* `banned/{uid}` がある ID は、登録も更新も拒否。
* **管理者** = 匿名でないログインで、`admins/{自分の uid}` がある。記録の `status` **だけ**を書き換えられる (タイム・絵・名前は書き換えられない)・記録を削除できる・`banned` を書ける・通報を読める / 消せる。
* 同じ決まりを TypeScript で書いたもの (`src/ranking/policy.ts`) を、開発用のモックとテストの偽サーバーが使う。**ルールを変えたら、policy.ts も揃える**。

### 絵のデータ
* セーブデータの形 (座標を小数の文字で持つ) は大きい (線の多い絵で数百 KB。Firestore の 1 件は約 1MB まで)。ランキング用には、座標を 0〜4095 の整数にして 1 点を 4 文字で書く (1/5 以下になる)。
* 上限は 150,000 文字。超える絵は、線の点を間引いて収める (始まりと終わりは残す)。それでも収まらなければ、姿なしで登録する。
* 一覧 (TOP 100) を読む時は絵を読まない。姿は、👁 を押した記録の分だけ読む。
* 他人の絵は信用しない: 読み込んだら、手元の絵と同じ検査 (`sanitizeDrawing`) を通し、立体にできなければ「表示できません」と出す。

### この作りで残ること
* 審査中・非表示の記録の絵と名前も、Firestore には保存されていて、**ゲームの画面には出ないが、Firestore を直接読む方法を知っている人には読める** (読み取りを「だれでも可」にしているため)。ゲームのランキングに載るわけではない。
* 審査の基準は管理者の判断 (アプリは判断しない)。承認までの間、上位の姿は「審査中」になる。
* タイムの不正は、今までどおり「明らかな異常値の排除」まで。管理者アプリで、不自然な記録を手で消せる。

## 4. 管理者アプリ (`/admin/`)

* 場所: ゲームのサイトの `/admin/` (例: `https://<ユーザー名>.github.io/rakugaction/admin/`)。検索には出さない (`noindex`)。
* **URL を知られても、操作は Firebase のルールが拒否する** (管理者のログインが要る)。
* **見本で試す**: URL の最後に `?mock` を付けると、ログインなしで、作り物のデータを操作できる (何も保存しない・どこにも送らない)。Firebase の準備の前に、画面を確かめられる。

### できること
* **審査待ち**: TOP 20 に入っている「審査中」の記録を、順位の高い順に並べる。
* 記録を選ぶと: **3D の姿** (回して見られる。ゲームと同じ立体化)・**名前** (大きく)・タイム・各ステージのタイム・能力値・登録した時刻・絵のデータの大きさ。
* **決める**:「✔ 承認」「🚫 非表示」「↩ 審査中に戻す」「🗑 記録を削除」「🗑 削除して、再登録を禁止」。承認 / 非表示を押すと、次の審査待ちへ進む。
* **通報**: 通報された記録を、件数の多い順に。確認したら「通報を片づける」。
* **すべての記録** (TOP 100): 状態で絞って、あとから変え直す・不自然なタイムの記録を消す。
* **禁止した ID**: 再登録の禁止を解く。

### 作り
* `admin/index.html` + `src/admin/` (別の入口・別のファイル。ゲームの入口からは読まれない)。立体化・絵の検査・記録の検査は、ゲームと同じコードを使う。
* 機能を足す時: `AdminFeature` (`src/admin/shell.ts`) を実装して、`src/admin/main.ts` の一覧に足す。ログインと「管理者かどうか」の確認は、枠の手前で済んでいる。
* ログイン: Google のログインボタン (Google Identity Services) が返す ID トークンを、Firebase の ID トークンに交換する (REST。SDK は入れていない)。端末に残すのは、ログインを続けるための更新トークンだけ (ログアウトで消す)。
* **パスワード・管理者の鍵・サービスアカウントの鍵・OAuth のクライアント シークレットは、どこにも置かない**。設定ファイルに書くのは、公開してよい識別子 (API キー・プロジェクト ID・OAuth クライアント ID) だけ。

## 5. 準備の手順 (ユーザーが行う)

1. **Firebase のプロジェクトを作る** (無料の Spark プラン)。[Firebase コンソール](https://console.firebase.google.com/)。
2. **Authentication → Sign-in method** で 2 つ有効にする:
   * **匿名 (Anonymous)** — プレイヤーの登録・通報用 (プレイヤーにログインの画面は出ない)。
   * **Google** — 管理者のログイン用。有効にすると「ウェブ SDK 構成」に **ウェブ クライアント ID** (`数字-英数字.apps.googleusercontent.com`) が出るので控える。
3. **Firestore Database を作る** (本番モード)。
4. **ルールを公開**: `firebase/firestore.rules` の内容を、Firestore の「ルール」タブに貼って公開する。**ここで文法の誤りがあれば、コンソールが教えてくれる** (このリポジトリでは、ルールを実際に動かして確かめられていない)。
5. **Google のログインを、サイトから使えるようにする**: [Google Cloud コンソール](https://console.cloud.google.com/) → 同じプロジェクト → 「API とサービス」→「認証情報」→「Web client (auto created by Google Service)」を開き、**「承認済みの JavaScript 生成元」** に、ゲームのサイトの生成元 (例: `https://<ユーザー名>.github.io`) を足す。手元で試すなら `http://localhost:5173` も。
6. **設定ファイル** `public/ranking-config.json` を書く (`ranking-config.example.json` が見本):
   ```json
   { "enabled": true, "apiKey": "AIza…", "projectId": "your-project-id", "collection": "ranking", "googleClientId": "数字-英数字.apps.googleusercontent.com" }
   ```
   API キーとプロジェクト ID は、プロジェクトの設定 → 「全般」。どれも公開してよい識別子 (秘密の値は書かない)。
7. **公開** (push → GitHub Pages)。
8. **管理者を登録する**: `/admin/` を開いて Google アカウントでログイン →「このアカウントは、管理者として登録されていません」の画面に **ID** が出る → Firebase コンソール → Firestore → コレクション `admins` を作り、**その ID をドキュメント ID** にしたドキュメントを 1 つ作る (中身は何でもよい。例: `role` = `owner`) →「もう一度確かめる」。
9. (おすすめ) API キーに制限をかける: Google Cloud コンソールの API キー →「HTTP リファラー」をゲームのサイトだけに・「API の制限」を Identity Toolkit API / Token Service API / Cloud Firestore API だけに。
10. (おすすめ) Firestore →「インデックス」→「単一フィールド」→ 除外を追加: コレクション `ranking`・フィールド `look`・すべて無効。大きな文字列を索引に入れない (保存の容量の節約)。

* ブラウザ: ゲーム (`?ranking=mock`) で、承認済みだけ名前と 👁 が出る・3D が開く。管理者アプリ (`/admin/?mock`) で、審査待ち → 承認 → 次へ・通報・2 列 / 1 列の並び。

## 7. 最初に確かめること (本物の Firebase で)
1. ルールが公開できる (文法の誤りが出ない)。
2. ゲームで ALL STAGES を完走 →「ランキングに登録」→ ランキングに、タイムと体型タイプ名 +「審査中」で載る。
3. `/admin/` にログイン → 審査待ちに出る → 3D と名前を確認 →「承認」→ ゲームのランキングで、名前と 👁 が出る。
4. 別のブラウザ (別の匿名 ID) で、その記録の 👁 →「⚑ 通報」→ 管理者アプリの「通報」に出る。
5. 管理者アプリで「削除して、再登録を禁止」→ 元のブラウザで、もう一度登録しようとすると拒否される。
6. 管理者として登録していない Google アカウントでログインすると、「登録されていません」と出て、操作できない。

うまくいかない所があれば、どの手順で何が出たかを教えてもらえれば直す (ルール・ログインは、実物でないと確かめられない部分)。
