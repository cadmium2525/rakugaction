* ヘッドレス/非表示タブでは rAF が止まる → `PlayScene.tick(dt)` を公開して自動テストから駆動できるように。

## PHASE 2: ラクガキエディタ

### 実装
* `src/drawing/model.ts` — ストローク列 (pen/erase/fill) のデータモデル、上限 (op 400/パーツ, 点 3000/ストローク)、座標は 1/4096 に量子化。パーツ = body/head/armLeft/armRight/legLeft/legRight。左 = 画像の右 (+x)。
* `src/drawing/raster.ts` — **Canvas 非依存**のソフトウェアラスタライザ (384²)。距離ベース AA、消しゴム、閉領域の塗りつぶし (外周に触れる領域は塗らない/線のにじみは塗りの上に重ねる)、ライブ描画と一括再生が一致。エディタ表示と 3D 化の元データが同一。
* `src/drawing/sanitize.ts` — 壊れた/悪意あるデータ (NaN/Infinity/範囲外/不正色/巨大) を安全な形へ。例外を投げない。
* `src/drawing/editorState.ts` — パーツ別 Undo/Redo、全消去 (Undo 可)、全リセット、左右コピー (OFF にすると反転コピーが出発点)。
* `src/drawing/defaults.ts` — 空のパーツは既定形状 (カプセル) で補う → 「何も描かなくても成立」。
* `src/character/layout.ts` — 6 パーツのマスクから頭/胴/腕/脚の配置を決定 (重ねて接続する方針)。PHASE 3 の 3D 化も同じ結果を使う。
* `src/ui/editor/*` — 4 ステップ (からだ→あたま→うで→あし)、ガイド、ペン/けす/ぬる/もどす/すすむ/ぜんぶ、12 色、4 太さ、ライブ合成ミニプレビュー、プレビューモーダル。
* `src/ui/titleScreen.ts`, `src/app/app.ts` — タイトル → エディタの画面遷移。ゲームシーンは離れる時に WebGL ごと破棄。

## PHASE 3: 2D→3D 生成 + 誕生演出

### 実装
* `src/character/maskOps.ts` — 距離変換 (Felzenszwalb 厳密 EDT)、穴埋め (外周 8 近傍連結を外とみなす)、4 近傍ラベリング、小片除去 (最大成分は必ず残す)、膨張、内接円半径。
* `src/character/contour.ts` — ピクセル境界追跡 (ピンチ点は右折して成分を分離 = 常に単純な輪郭)、[1 2 1] 平滑化、Douglas-Peucker、自己交差検査。**平滑化/許容誤差を段階的に弱めて再試行 → 最後は凸包**で、どんな絵でも単純多角形を得る。
* `src/character/cleanPart.ts` — シルエット整形 (穴埋め → ゴミ除去 → 最小の太さ補正 + 常時 2px 膨張) とテクスチャ生成 (192²、囲まれた未塗りは紙色、膨らませた縁は近傍色でにじませ)。
* `src/character/partGeometry.ts` — ExtrudeGeometry + ベベル (bevelOffset 負 = シルエットは描いた形のまま) + creased normals + 平面投影 UV。**側面/ベベルは輪郭線の内側の色をサンプル**して、黒い縁取りが側面全体に回らないように。裏面は暗く。三角形予算 3200/パーツ (超えたら輪郭を粗くして作り直し)。
* `src/character/builder.ts` — `buildCharacter(drawing)`: 6 パーツ → 整形 → レイアウト → rig 組み立て (root→body→head/armL/armR/legL/legR、関節がピボット)。前面をそろえた Z 配置 (2D プレビューと同じ重なり)。例外を投げない。
* `src/render/renderHost.ts` — WebGL (canvas) をアプリ全体で 1 つに共有 (ゲーム/誕生など複数ビューが借りる)。GameView は借りる側へ。
* `src/render/showcaseView.ts`, `src/ui/birthScreen.ts` — 誕生演出: 平らなラクガキが浮かぶ → ポンッと立体化 (z スケールがエラスティックに膨らみ回転) + キラキラ → 着地スカッシュ + 砂ぼこり → 「たんじょう！」→ ボタン。タップでスキップ。ターンテーブル待機。
* `src/dev/doodles.ts` — 極端ラクガキ 15 種のフィクスチャ (テストと `?birth=<name>` で共有)。

## PHASE 4: 手続きアニメーション

### 実装
* `src/character/animator.ts` — `CharacterAnimator`: Idle / Walk / Run / Jump / Fall / Land を、リグのピボット回転だけで表現 (手足の伸縮なし)。
  * 歩行周期は速度と脚の長さから決定、振れ角は手足の長さで補正 (長い手足は小さく/短い手足は大きく)、左右逆位相、走りで前傾。
  * Jump: 腕を上げ脚を前後に / Fall: 手足を広げてばたつく / Land: 衝撃に比例したスカッシュ & ストレッチ (Y 潰れ・XZ 膨張) と脚の曲げ。
  * 全チャンネルを指数スムージングで遷移。着地は `landCount` の増加で検出。
  * **地面に埋まらない保証**: 手足の外接箱の 8 隅を毎フレーム root 座標へ変換し、脚の最下点が 0 未満なら体ごと持ち上げる。**長すぎる腕**は構築時に立ち姿で clearance が取れる角度まで外へ開く (rest splay)。
* `PlayerView` をアニメーター駆動に置換 (仮の傾き/スカッシュを廃止)。`ShowcaseView` も待機にアニメーターを使用 (`demoState` でその場 walk/run/jump/fall を再生可)。
* `PlayerController.landCount` 追加。毎フレームの allocation を排除 (pose の再利用)。

## PHASE 5: 能力生成

### 実装
* `src/character/colorClass.ts` — RGB → 赤/黄/緑/青/紫/無彩色 へのソフト分類 (色相環の隣り合うアンカーへ線形配分: 橙=赤+黄, 水色=青+緑, ピンク=赤+紫。黒/白/灰/茶は無彩色)。
* `src/character/measure.ts` — 形状計測 (全高/幅/各パーツの面積・寸法・厚み/重心/接地幅/脚の長さ/左右非対称) と色の使用割合。`measureDrawing()` はジオメトリ無しの軽量版。
* `src/character/statGen.ts` — `computeStats()`:
  1. 形状特徴量 (基準との対数比) → 6 能力 (大きい体: HP/DEF/WEIGHT↑ SPEED/JUMP↓、長い脚: SPEED/JUMP↑、太い腕: POWER/WEIGHT↑、太い脚: JUMP↑、縦長で小さい体: SPEED↑)。キャンバスに上限がある量 (脚/腕の長さ/全高) は「描ける最大」で +0.7 になるよう伸ばして、長い側/短い側の効果を釣り合わせる。
  2. 色 (赤=POWER 青=DEF 緑=SPEED 黄=JUMP) を **最大 +20% の副次補正**として加算。紫の割合は `special`。
  3. **能力値の予算 (対数の平均) を 0 にそろえる** → ある能力を伸ばせば他が必ず下がる (最強形状が構造上作れない)。色補正も予算の内側。
  4. ソフトクランプ (約 45〜222)。traits: size (体の大きさ → 見た目/当たり判定), reach (リーチ), stability (足幅/重心/脚の長さ)。
  5. `describeBuild()`: 重量型/高速型/ジャンプ型/力持ち型/守り型/バランス型/極端型 のラベル。
  * 基準 (REF) = エディタのガイド形状をなぞった `referenceDoodle()` の計測値 → 全能力 100。
* `src/game/params.ts` を再較正: 最高速度 ≈ 4.7〜10 m/s、ジャンプ初速 ≈ 7.4〜14 m/s に収まる指数 (SPEED^0.5, JUMP^0.4)。WEIGHT は加速/摩擦/旋回/風耐性/沈みやすさ/ノックバックに効く。
* `buildCharacter()` が能力解析まで行い、全高 = 1.6m × size。`BuiltCharacter.analysis` を誕生画面の **能力カード** (`src/ui/statCard.ts`: ビルドラベル + 6 本のバー + 「ふつう」目安線 + なまえ入力) に表示。誕生後の「あそぶ」は描いた形から決まった能力で走る。
* `src/character/record.ts` — 保存単位 `CharacterRecord` (PHASE 14 で使用。`STAT_FORMULA_VERSION` で式変更時に再計算)。
* `src/dev/randomDoodle.ts` (plausible/wild の 2 プロファイル)、`src/dev/doodles.ts` に基準ラクガキ/バリエーション/**テストビルド元ラクガキ**を追加。**TEST_BUILDS の能力値は実際のラクガキの計測値と一致**させ (テストで検証)、「現実に作れる範囲」でバランスを検証できるようにした。

実際に作れる両端: 重量型 (giant) HP131 DEF125 WT131 / SP62 JP77、高速型 (speedy) SP159 JP128 / WT80、力持ち POWER 163。

### 発見して修正した問題
* 長い脚の効果が弱い (ガイドの脚が 76% なので上側の余地が小さい) → `lrCap` で上限を考慮した特徴量に。
* SPEED と JUMP が同じ特徴量で相関 0.95 → 脚の太さ (JUMP)・体の縦横比 (SPEED) で分離 (相関 0.6)。
* 基準ラクガキの計測が解像度に依存 → 基本膨張を比率指定に、REF を本番解像度 (384) で再計測。
* 既定パーツの色が肌色で色補正を得る → 無彩色に変更。
* テストビルドが「作れない能力」だった → 実ラクガキの計測値に差し替え、一致テストを追加。
* WEIGHT の慣性テストが SPEED の違いに左右された → 同一 SPEED で WEIGHT だけ変えて比較。

## PHASE 6: STAGE 1 草原 + ステージ共通基盤

### 実装 (共通基盤)
* **PathBuilder** (`src/stages/pathBuilder.ts`): 経路上のカーソルが伸びていく記述 DSL。`flat/ramp/gap/turn/checkpoint/goalHere/hazard/breakable/moverBridge` で、衝突ジオメトリ・チェックポイント・ゴール・**ボット用ウェイポイント (着地目標つき)** を同時生成。

### 発見して修正した重大バグ (ボットの実走で発覚)
1. **衝突法線の取り違え**: Rapier の `CharacterCollision.normal1` が障害物の法線 (normal2 はキャラ側)。`normal2` を使っていたため **壁に当たっても水平速度が消えず**、「止まっているのに速度 7」になっていた。→ normal1 に修正 + 回帰テスト (壁押し付け/斜め衝突)。
2. **kinematic の移動床の上で前進できない** (Rapier KinematicCharacterController が毎ステップ 20 回の衝突を起こす) → 移動床を fixed ボディ + 毎ステップ `setTranslation` に変更。回帰テスト追加。
3. 攻撃の `attackHandled` で 1 回の攻撃が 1 つの箱しか壊せなかった → 対象ごとの Set に。
4. 通路の高さが最大サイズ (2.4m) より低くて詰まった → 通路高 3.3m + 設計ルール (必須経路の天井 ≥ 2.7m) を追加。
5. 近道の橋が動く橋と同じレーンで、橋に飛び乗れて近道が無効 → 別レーンに分離。

## PHASE 7: STAGE 2 強風の谷

### 実装
* **風** (`src/game/wind.ts`): 風域 (AABB + 風速ベクトル) と強さの時間変化 (`gust` = 周期 period のうち on 秒だけ吹く / `pulse` = 常に吹き強さが脈打つ)。位置を直接押す方式で、`windResistance = 1/WEIGHT^1.8` (重い = 風に強い) と接地係数 0.55 (空中は 1.0)。`calmFor`/`timeUntilCalm` で「風が止む間に渡れるか」を判断できる。
* **ボットの判断**: 風域の手前で「今すぐ斜めに進んで渡る (前進速度 = √(最高速度² − 流される速度²))」か「風が弱まるまで待つ」かを所要時間の見積りで決める。細い橋は線分追従 (少し先の中心線を狙う) で流されを抑える。
* `PathBuilder.windSpan/windZone/branch/jumpTo/takeRoute` と `RouteSet` (共通区間 + 分岐からルート 'main'/'fast' を合成)。
* **STAGE 2** (`src/stages/stage2.ts`): A そよ風の入り口 → B 横風の細い橋 5 スパン (6m ごとに避難所) → C 崖 (階段 / **上昇気流 + ジャンプで 4m の崖を越える近道**) → D 逆向きの橋 3 スパン → 山頂。横風 12.5m/s、突風は 6 秒周期で 4 秒吹き 2 秒止む。
* **風の可視化** (`windStreaks.ts`): 風域内を流れる白い筋 (1 draw call の InstancedMesh、強さで長さ/速さ/消失)。HUD に風向き (カメラ基準) + 強さの矢印、初回に「重いほど風に強い」ヒント。

### バランス計測 (ボット, 秒)
| build (WEIGHT) | 本道 | 近道 (上昇気流) | 備考 |
|---|---|---|---|
| JUMP (108) | 35.7 | 33.8 | 風を押し切って渡る |
| POWER (110) | 40.0 | 38.9 | 〃 |
| HEAVY (131) | 40.8 | ✗ | 近道は押し上げが足りない |
| EXTREME (163) | 43.2 | ✗ | 〃 |
| SPEED (80) | 56.1 | 50.2 | 風に抗えず、突風の止み間を待つ |
| STANDARD (100) | 58.1 | 58.0 | 〃 |
→ 重いほど有利 (HEAVY は STANDARD より約 30% 速い)。ただし軽いビルドも必ずクリア可能 (待てば渡れる + 近道)。
* 風速と「抗えるか」の境目: 同じ速さ比で見ると、速い=軽いビルドは風の影響が相対的に変わらない (速度と風の効きが相殺) ため、**効きの指数を 1.1 → 1.8 に上げて**重量差が時間に効くようにした。
