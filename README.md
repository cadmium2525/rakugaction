# ラクガキアクション (RAKUGACTION)

**自分で描いたラクガキが、そのまま 3D のキャラクターになって走り回る 3D アクションゲーム。**
スマホ (iPhone Safari / Android Chrome) を最優先に、PC のブラウザでも遊べます。サーバー処理は不要で、**GitHub Pages に置くだけ・運用費 0 円**。AI 画像生成や有料 API は使いません (描く → 3D 化 → 物理 → 保存まで、全てブラウザの中で完結します)。

* 描く: 指で「からだ・あたま・うで・あし」をなぞって描く (好きなように。極端な絵でも遊べる)
* 3D 化: 描いた輪郭を押し出して立体に。歩く・走る・ジャンプする動きは手続きアニメーション
* 能力: 体の形 (大きさ・長さ・重さのバランス) から HP / POWER / DEFENSE / SPEED / JUMP / WEIGHT が決まり、使った色が少しだけ味付けする
* 遊ぶ: 5 つのステージ + 全ステージ通しの **ALL STAGES TIME ATTACK** + オンラインランキング (任意)

> 開発の記録は [`docs/PROGRESS.md`](docs/PROGRESS.md)、設計は [`docs/DESIGN.md`](docs/DESIGN.md)、ランキングの設定は [`docs/RANKING.md`](docs/RANKING.md) にあります。

---

## 1. 起動方法 (開発)

Node.js 22.12 以上 (テストランナーの要件。ビルドだけなら 20.19 以上) が必要です。

```bash
npm install
npm run dev          # 開発サーバー (http://localhost:5173 。同じ Wi-Fi のスマホからは http://<PCのIP>:5173)
```

| コマンド | 内容 |
|---|---|
| `npm run dev` | 開発サーバー (`PORT=3000 npm run dev` でポート指定) |
| `npm run build` | 型チェック + 本番ビルド (`dist/`) |
| `npm run preview` | ビルドした `dist/` を Vite で配信 |
| `npm run preview:pages` | `dist/` を **GitHub Pages と同じサブパス** (`/rakugaction/`) だけで配信し、絶対パスの取りこぼしを検出する |
| `npm run lint` / `npm run typecheck` | ESLint / TypeScript (strict) |
| `npm test` | Vitest (ロジック・ヘッドレス物理・ボットでのステージ攻略) |

開発用の URL パラメータ (開発サーバー、または本番でも `?debug=1` を付けたときだけ有効):
`?doodle=STANDARD&stage=stage1` (テスト用キャラでステージを直接開く) / `&hub` / `&ta` / `?ranking=mock` (メモリ上のモックランキング) / `?arena`。
ブラウザの Console から `window.__rg` でアプリを操作できます (QA 用)。

## 2. GitHub Pages で公開する

1. GitHub に新しいリポジトリを作って push する (ブランチは `main`)。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **「GitHub Actions」** にする。
3. `main` に push すると [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) が **lint → テスト → ビルド → 公開** を実行する。完了すると `https://<ユーザー名>.github.io/<リポジトリ名>/` で遊べる。

アセットは全て相対パス (`base: './'`) なので、リポジトリ名のサブパスでもそのまま動きます。公開前に `npm run build && npm run preview:pages` で `http://localhost:8099/rakugaction/` を開くと、Pages と同じ条件で確認できます。
物理エンジン (Rapier の WASM) は JS に埋め込まれているので、追加ファイルや CORS の設定は要りません。初回の読み込みは約 1.9 MB (gzip)。

### オンラインランキングを有効にする (任意)
設定しなくてもゲームは完全に遊べます (ランキング画面が「準備中」になるだけ)。使うときは無料の Firebase (Spark) を用意して `public/ranking-config.json` を書き換えます。手順・不正対策・無料枠の目安は [`docs/RANKING.md`](docs/RANKING.md)。**管理者キー・サービスアカウントはリポジトリに置かないでください** (このゲームは必要としません)。

## 3. 使用ライブラリ

| ライブラリ | 用途 |
|---|---|
| [Three.js](https://threejs.org/) | 3D 描画 (キャラクターの押し出しメッシュ、ステージ、影、水面など) |
| [@dimforge/rapier3d-compat](https://rapier.rs/) | 物理 (キャラクターコントローラ、動く床、風、水、崩れる床)。動的 import で遅延読み込み |
| Vite / TypeScript | ビルド・型 (開発時のみ) |
| Vitest / ESLint / fake-indexeddb | テスト・lint (開発時のみ) |

UI フレームワークは使わず、DOM + CSS + Canvas 2D だけです。ランキングは Firebase SDK を使わず REST で直接通信します。

## 4. ゲーム仕様

### 4.1 ラクガキ → キャラクター
* エディタは 4 ステップ (からだ → あたま → うで → あし)。ペン / 消しゴム / 塗りつぶし / 元に戻す / 全消し / 左右コピー、12 色、4 種類の太さ。
* 描いた絵は「ストロークの列」として保持され、整形 (ノイズ・はみ出し・細すぎる線の補正) → 輪郭抽出 → 厚みをつけて 3D 化。どんな絵でも必ず何かのキャラクターになります (描き込みを制限しません)。
* 誕生画面で名前を付けて保存。キャラクターは最大 12 体まで。

### 4.2 能力 (トレードオフあり)
体の形が主、色が副。能力値は予算を配分する形で決まるので、**全部が高い体は作れません** (大きい体は強いが遅い、軽い体は速いが打たれ弱い、など)。

| 能力 | 主な決まり方 (形) | 色の補正 (最大で約 +20%) |
|---|---|---|
| HP | 体全体の大きさ・胴の面積 | — |
| POWER | 腕の太さ・腕の面積 | 赤 |
| DEFENSE | 体全体の大きさ・胴の面積 | 青 |
| SPEED | 脚の長さ・縦長で小さい体 (大きい体は遅い) | 緑 |
| JUMP | 脚の長さと太さ・小さい体 | 黄 |
| WEIGHT | 体全体の大きさ・腕脚の太さ (風・水・崩れる床との相性に効く) | — |

* 長い腕は攻撃のリーチが伸びる代わりに動作が遅くなり、脚が長いほど足元が不安定になります (`traits`)。
* 「全部を極端にして最強」は作れないよう、6 能力は対数で合計一定 (予算) に正規化されています。
* **紫 (特殊傾向)**: 紫の使用割合は `special` として記録・保存されますが、**現在ゲーム内の効果はありません** (今後の拡張枠。「既知の制限」参照)。

### 4.3 レベルと EXP
ステージクリアと ALL STAGES TIME ATTACK 完走で EXP が入ります (初回クリアが最も多く、ランク S は +50%)。**Lv.1〜20**。1 レベルごとに HP/POWER/DEFENSE/SPEED/JUMP が +0.75%、得意な能力 (上位 2 つ) にさらに +0.35%、Lv.10 と Lv.20 でハート +1。**WEIGHT は成長しません** (体の重さが変わるとステージとの相性が別物になるため)。個性を消さない穏やかな成長です。

### 4.4 ステージ
| ステージ | 特徴 | 有利になりやすい体 |
|---|---|---|
| ① 草原 | 空に浮かぶ草原 (雲海・浮島・風車・家・花畑・柵・看板)。広い丘・飛び石・動く橋・木箱の壁 (ACTION で壊せる)。**てき 9 体** | 速い体 (長いギャップを跳び越す近道) / 攻撃力が標準以上 (木箱の抜け道・トゲまるを倒す) |
| ② 強風の谷 | 横風 (体重で押し返す)・突風 | 重い体 |
| ③ 水没神殿 | 水位が変わる・浮力 (JUMP で浮く / ACTION で潜る)・狭い扉 | 軽くて小さい体 |
| ④ 崩れる遺跡 | 乗ると崩れる足場・高い段差・木箱の壁 | ジャンプ力のある体 |
| ⑤ 巨人の塔 | 4 つのフロアと山頂。各フロアに「誰でも通れる長い外周 (動く鉄球)」と「条件つきの近道」(上昇気流・木箱・跳躍・炎の通路)、最後は崩れる橋 | 総合力 (近道が得意なビルドはフロアごとに違う。HP・DEFENSE は炎の通路で効く) |

※ **てき・作り込み (小道具や看板) は今のところ STAGE 1 だけ**です (試作)。② 以降は今後広げます。

どのステージも、複数のビルド (標準・速い・高く跳ぶ・重い・力持ち・極端) でボットが **死なずにクリアできる** ことをテストで保証しています。得意なステージの近道があり、全ステージで最速になる体は無いように調整してあります (合計タイムの最大/最小 = 約 1.5 倍。詳細は PROGRESS の「全ステージ通しのバランス調整」)。

### 4.5 てき
STAGE 1 に 4 種類 (9 体) います。看板に近づくと、説明が画面上部に出ます (操作名は PC / タッチで切り替わります)。触れるとダメージ (DEFENSE で軽減、ハートが 0 で復活) とノックバックを受けます。

| てき | ふるまい | 倒し方 |
|---|---|---|
| ぷるん | ゆっくり左右に歩く | ふんづける / ACTION (誰でも倒せる) |
| ぴょんた | ためて、ぴょんと跳ねながら進む | ふんづける / ACTION |
| トゲまる | 転がって巡回。**上からふむとトゲで痛い** | ACTION だけ。**攻撃力が標準以上**のキャラだけが倒せる。足りないと**はね返され** (少し後ろへ弾かれ、直後は無敵)、避けて通るしかない。本道の足場 (階段状の丘) では左半分を往復していて、右側に常に安全な通り道がある |
| おいかけくん | 近づくと追いかけてくる (決まった広場の外へは出ない) | ふんづける / ACTION |

* **ふんづけ**: 落ちながら敵の上に乗ると倒せて、上にはね返る (ジャンプボタンを押し続けていると高くはね返る)。
* **チェックポイントを通ると HP が全回復**し、**そこまでに倒した敵は復活しません** (やられて戻っても、背後の敵が戻ってきません)。まだ倒していない敵は、やられて復活すると元の位置に戻ります。
* **ノックバックだけで足場から落ちないよう**、足場の端が近いと弾かれる距離が縮みます。ゴールした後 (演出中) は敵や罠でダメージを受けません。
* ステージクリア時に「撃破した敵 n 体」が出て、1 体につき EXP +3 (1 回のクリアで最大 +30。くりかえしのクリアでは他の EXP と同じく減ります)。
* 敵の位置は経過時間だけで決まり (おいかけくんだけはプレイヤーの位置で動く)、同じ操作なら同じ結果になります。

### 4.6 ALL STAGES TIME ATTACK
同じキャラクターで ①〜⑤ を連続して走り、合計タイムを競います。
* タイマーは単調増加時計 (`performance.now()`)。端末の時刻を変えても影響されず、ロード・演出・ポーズ・バックグラウンドの時間は含まれません。
* ステージ間でスプリットを表示。ベストは端末に保存。やり直しは「最初のステージから」。
* 実時間とシミュレーション時間のずれなど異常な記録には自動でフラグが付き、ベスト/EXP/ランキング送信の対象外になります。

### 4.7 オンラインランキング
結果画面の「ランキングにのせる」で送信。TOP100・自分の記録・自分の順位を見られます。記録されるのは名前・総タイム・各ステージのタイム・レベル・能力値・バージョンなど。ランキングが使えない (未設定・オフライン・サーバー障害) ときも、**ゲームの進行や保存には一切影響しません**。仕組みと不正対策 (最善努力で、完全防止は目標外) は [`docs/RANKING.md`](docs/RANKING.md)。

## 5. 操作方法

| | スマホ (横向き) | PC |
|---|---|---|
| 移動 | 画面の左側をタッチ → **仮想スティック** | `WASD` / 矢印キー |
| ジャンプ | 右下の **JUMP** (水中では浮く。てきの上に落ちると、ふんづけてはね返る) | `Space` / `Z` |
| アクション | 右下の **ACTION** (木箱を壊す / てきに体当たり / 水中で潜る) | `X` / `J` / `Shift` |
| カメラ | 画面の右側 (左から 42% より右) をスワイプ | (自動追従) |
| ポーズ | 右上の **Ⅱ** | `Esc` / `P` |

* **縦持ちのときは「横向きにしてください」を表示し、プレイ中なら自動でポーズ**します。横に戻して「つづける」で再開。
* iPhone の切り欠き (ノッチ) やホームバーを避けて (`safe-area`)、ボタンを配置します。
* 設定 → 画質 (じどう / ひくい / ふつう / たかい。「じどう」はフレームレートに応じて動的に解像度を調整)、全画面 (対応端末のみ)、セーブデータの削除。

## 6. セーブ仕様
* 保存するもの: キャラクター (ラクガキそのもの + 名前 + 能力)・EXP/レベル・ステージごとのベストとクリア状況・ALL STAGES のベスト・設定。
* 保存先は **IndexedDB** (使えなければ localStorage、それも無理ならメモリ)。ネットワークには送りません。
* **バージョン付き** (`schemaVersion`)。古いデータは起動時にマイグレーションされ、**新しいバージョンのデータは上書きしません** (読み取り専用で警告)。
* チェックサム付きの 2 世代 (main / backup) を持ち、書き込み途中の停止・手動編集・容量切れで壊れても backup から復旧します (壊れたデータは調査用に別枠へ退避)。復旧時は画面でお知らせします。
* 能力値の計算式を変えた場合は、起動時に保存されたラクガキから再計算します。
* ホーム画面に追加 (PWA) すると、ブラウザによるデータ消去を受けにくくなります (iOS Safari は一定期間操作しないとサイトデータを消すことがあります)。

## 7. 既知の制限
詳しくは `docs/PROGRESS.md` の「未検証」「既知の課題」を参照。主なもの:

* **実機は未検証**: タッチの感触・遅延、iOS Safari の挙動 (アドレスバーの出入り、全画面、IndexedDB の消去ルール)、発熱・バッテリー、低価格端末の実フレームレート。自動検査は「ブラウザのエミュレーション + PointerEvent の合成」で行いました。
* **本物の Firebase への書き込みは未検証** (実際の Firestore ではまだ試していません。モックとルールの整合テストのみ)。
* **紫 (特殊傾向) はゲーム内の効果が未実装**です (値の記録のみ)。赤・青・緑・黄の補正は動作しています。
* 効果音・BGM はありません。
* **STAGE 2〜5 には敵・看板・作り込みの小道具がまだありません** (STAGE 1 で試作して方向性を確かめている段階)。
* STAGE 1 は小道具が多い分、描画が重めです (画質「ひくい」でも約 4.7 万三角形・45 描画呼び出し。表面の模様は「ひくい」では無効)。実機でのフレームレートは未確認です。
* バランス: SPEED 型 (速い・軽い・跳べる) が得意なステージが多く、極端な体 (EXTREME) は大半のステージで遅めです。それでも全ステージをクリアでき、重い体が勝つステージ (風)・攻撃力が活きる近道 (木箱) があります。
* 極小の横画面 (568×320 = iPhone SE 初代相当) ではボタンが 27px 高と小さめです。
* ラクガキの描きかけ (下書き) の自動保存・キャラクターの名前変更は未実装です。
* `pagehide` での最後の保存は非同期のため、タブを即座に閉じると直前の変更を取りこぼすことがあります (通常は変更の 0.4 秒後に保存済み)。

## 8. ディレクトリ構成
```
src/
  app/        アプリ本体・画面遷移・ステージの進行・縦持ちガード
  character/  ラクガキ → 輪郭 → 3D → リグ・手続きアニメ・能力の計算
  drawing/    ストロークモデル・ラスタライズ・サニタイズ・エディタ状態
  game/       GameSim (Rapier) ・プレイヤー制御・ボット  ← DOM/WebGL に依存しない
  stages/     5 ステージの定義 (PathBuilder DSL)・木箱の抜け道
  render/     Three.js のビュー・水・空・影・品質
  ui/         画面 (title/editor/birth/hub/result/ranking/settings)・HUD・CSS
  input/      キーボード・タッチ (仮想スティック/ボタン/カメラ)
  progression/ EXP・レベル   timeattack/ ALL STAGES   ranking/ ランキング   save/ セーブ
tests/        Vitest (ロジック・ヘッドレス物理・ボット攻略・バランス)
docs/         DESIGN / PROGRESS / RANKING
firebase/     ランキング用のセキュリティルール
scripts/      確認用スクリプト (GitHub Pages 風サブパス配信)
```
シミュレーション (`src/game`、`src/stages` など) は DOM/WebGL に依存しないので、Node 上でヘッドレスに実行してテストできます (単位 m / s、固定 60Hz、Y-up)。

## 9. ライセンス・素材
コード・画像は全てこのリポジトリ内で作成したものです (外部の画像素材は使っていません)。**効果音・BGM はありません** (音声の実装は今後の拡張です)。
